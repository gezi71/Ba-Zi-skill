# 核心判断的证据检查

涉及结构推演的回答，核心判断先整理成 JSON 列表；字段路径使用 JSON Pointer，
数组索引从 0 开始。候选模式另用从 1 开始的 `候选编号` 指向该候选代表排盘。
解释整个时间范围时仍需检查该组输入情景与起运范围，不能把代表盘当全部情景。

```json
[
  {
    "类别": "结构线索",
    "文本": "月令藏干支持该候选，完整成败条件尚未评估。",
    "字段": ["/传统结构/格局候选/0"],
    "规则编号": ["ZP-MONTH-01"]
  }
]
```

将原始排盘与核心判断存入临时目录，执行：

```bash
python scripts/check_reading.py --chart /tmp/chart.json --reading /tmp/reading.json
```

允许类别为事实、结构线索、文化解释。本版不接受成格、合化、用神判定；
结构或解释须有有效规则编号，不能只有强弱评分证据；候选判断必须声明归属。
调候待校影摘录不列入可执行规则编号。

检查器只能核验类别、字段存在、规则编号和候选归属，不能证明自然语言文本忠实。
交付前还要逐句检查：

- 未评估的必要条件是否仍被说成已成立；同见、支组是否被说成实际制化或合化。
- 有没有把“未见所列干扰因素”写成“完全没有干扰”。
- 是否把同五行根与同干根混同、把有根写成力量必足。
- 是否将条件化观察写成确定事件，或由分数、五行缺项直接取用神。
- 是否按用户问题回答，并保留原始告警、候选差异及资料校对限制。

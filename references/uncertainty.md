# 候选盘比较与不确定性

## 使用

```bash
# 已认可的出生时间范围；小时较宽也逐分钟检查，避免只排两端漏掉中间时柱
python scripts/bazi.py --date 2000-01-01 --time-range 13:00-17:00 --city 北京 --format json

# 大陆夏令时读数未确认；输出输入假设，不替用户确认读数
python scripts/bazi.py --date 1990-06-15 --time 14:30 --city 北京 --gender male --compare --format json

# 跨午夜；日期参数属于范围开始那一天
python scripts/bazi.py --date 2000-01-01 --time-range 23:30-00:30 --city 北京 --format json
```

`--time-range` 与 `--time` 二选一。范围含端点，结束更早自动到次日；开始与结束
相同时只排该分钟，不表示全天。不知道任何时间时，用户接受后可用 `00:00-23:59`，
但大范围共同信息有限，不得因此硬解时柱。

时间范围不会自动猜夏令时口径；同时存在该歧义时加 `--compare`。
`--compare` 默认保持已有晚子时流派，可另外运行明确的 `--late-zishi` 口径，
不要用候选数量、报告“更像本人”等理由裁决流派或时辰。

## 三种独立情景

1. 出生时间范围：按用户提供的钟表时间逐分钟穷举，单次最多跨一个午夜。
2. 中国大陆夏令时：在表内日期且标准时区 +8 时，比较未回拨与回拨1小时。
   这只是“出生于大陆且读数尚未确认”的假设，不能用于海外推断。
   已明确 `--dst-adjust` 时不再加入未回拨情景。
3. 交节精度：仅在距离节气约 ±15 分钟时加入节气时刻 -15/0/+15 分钟情景。
   移动的是节气参照，不是出生时刻；该测试反映边界敏感性，未提高天文精度。

海外使用出生时实际 UTC 偏移（包括当地夏令时）；脚本不含海外历史时区数据库。
缺经度时不做真太阳时校正，候选范围不能弥补缺少经度的信息。
大陆夏令时日期表按整日处理，转换当天凌晨精确规则尚未支持；
这种情况下请核对历史转换资料，不把整日表当分钟级事实。

## 如何读输出

- `共同四柱`：所有采样情景一致的柱，只代表该层数据一致，不证明个人事件结论。
- `变化四柱`：涉及变化的柱，其十神、强弱、格局候选与运程需按各盘分别读。
- `候选[].输入情景`：该四柱对应的时间段、夏令时假设和节气偏移；各情景不等概率。
- `代表排盘`：该组一个输入的完整数据与规则来源，不代表组内所有太阳时、告警及起运日期。
- `候选[].告警`：该组全部情景的告警，解释时必须读取，不仅看代表排盘。
- `起运日期范围`：同一四柱组仍可能因出生时间/节气情景不同而有不同起运日期；
  大运每十年的交界也随此范围变化。不能用代表日期认定用户当前大运。

先告知输入假设，再讲共同信息，最后说明差异。范围过宽或当前问题依赖变化字段时，
暂缓该判断，并指出需要确认哪项输入。性别未知时没有大运或起运日期，不自行补全。
